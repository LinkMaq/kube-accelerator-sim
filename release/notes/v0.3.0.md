# 中文

## kube-accelerator-sim v0.3.0

v0.3.0 让本地只读集群模拟清单更容易启动、共享和长时间查看：`kasim ui`
现在默认使用 kubectl 的当前 kubeconfig/context，支持显式监听地址，并提供跟随系统
偏好的浅色/深色主题。Kasim 仍然只连接已有 Kubernetes 集群，不负责产品 CLI
之外的集群生命周期。

### 主要变化

- `kasim ui` 不再要求每次显式提供目标参数。默认遵循标准 kubeconfig 加载规则和
  current-context；需要覆盖时仍可使用 `--kubeconfig` 与 `--context`。
- 新增 `--host`，可选择 `127.0.0.1`、具体主机地址或通配监听地址。默认仍只监听
  回环地址；非回环监听会明确提示未加密 HTTP 风险，并继续执行 Host 校验。
- 新增浅色/深色主题切换。未显式选择时跟随系统主题及其实时变化；显式选择只写入
  `theme=light|dark` 查询参数，不使用浏览器存储，也不会移动或泄漏 fragment 中的
  临时访问能力。
- 主题控件在桌面和移动端均保持可见，提供中英文文本、键盘焦点、ARIA 状态、
  44 CSS 像素触控目标和 reduced-motion 行为。
- 根命令与 `ui` 子命令均支持 `-h` / `--help`，帮助输出不连接 Kubernetes。
- 更新操作 Skill、中英文在线文档、UI 规范、ADR、浏览器契约和发布包体预算检查。

### UI 安全边界

每次 `kasim ui` 启动都会生成新的 256 位临时访问能力，并只把它放在 URL fragment
中。服务仍然只提供 `GET`/`HEAD` 只读表面，没有写接口、第三方资源或宽松 CORS。
非回环监听必须由用户显式选择；它使用未加密 HTTP，因此只应在受限可信网络中使用，
完整访问 URL 应按临时密钥处理。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64 原生
  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- 发布收据逐平台记录 UI 原始/gzip 资源大小和压缩二进制增量，并继续强制执行
  256 KiB、96 KiB 和 1 MiB 上限。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.3.0`
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.3.0`

### 兼容性与真实性边界

Kubernetes 支持范围仍严格限定为 1.30–1.36；`scheduling` 支持整个范围，稳定 DRA
控制平面模拟限定为 1.34–1.36。Kasim 只模拟 Kubernetes 控制平面可见行为，不提供
物理设备、加速计算、厂商驱动、遥测、NUMA、CDI 或容器设备运行时保真度。未知健康
信息不会从 Node Ready、容量或资源名推断。

# English

## kube-accelerator-sim v0.3.0

v0.3.0 makes the local read-only Cluster Simulation Inventory easier to
start, share, and keep open. `kasim ui` now defaults to kubectl's current
kubeconfig/context, supports an explicit listen host, and provides light and
dark themes that follow the operating-system preference. Kasim still targets
only existing Kubernetes clusters and does not move cluster lifecycle into
the product CLI.

### Highlights

- `kasim ui` no longer requires target flags on every invocation. It follows
  standard kubeconfig loading and the current context by default, while
  retaining `--kubeconfig` and `--context` overrides.
- Added `--host` for loopback, a specific host address, or a wildcard listener.
  Loopback remains the default; non-loopback listeners emit an explicit
  unencrypted-HTTP warning and retain Host validation.
- Added light/dark theme switching. With no explicit choice the UI follows
  live system-theme changes. An explicit choice uses only the
  `theme=light|dark` query parameter, never browser storage, and does not move
  or expose the ephemeral capability held in the fragment.
- The theme control remains visible on desktop and mobile, with bilingual
  text, keyboard focus, ARIA state, 44 CSS-pixel targets, and reduced-motion
  behavior.
- The root command and `ui` subcommand now accept `-h` / `--help` without
  contacting Kubernetes.
- Updated the operation Skill, bilingual online documentation, UI
  specifications, ADR, browser contracts, and release-size budget coverage.

### UI security boundary

Every `kasim ui` launch creates a new 256-bit ephemeral capability and places
it only in the URL fragment. The server continues to expose a read-only
`GET`/`HEAD` surface with no mutation API, third-party assets, or permissive
CORS. Non-loopback listening must be selected explicitly and uses unencrypted
HTTP, so it belongs only on a restricted trusted network. Treat the complete
access URL as a temporary secret.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and
  a Sigstore signature.
- The release receipt records raw/gzip UI asset sizes and compressed binary
  deltas for every platform, retaining the 256 KiB, 96 KiB, and 1 MiB limits.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.3.0`
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.3.0`

### Compatibility and truth boundaries

Kubernetes support remains strictly bounded to 1.30–1.36: `scheduling` spans
the full range, while stable DRA control-plane simulation remains 1.34–1.36.
Kasim simulates Kubernetes-visible control-plane behavior only. It does not
provide physical devices, accelerator computation, vendor drivers, telemetry,
NUMA, CDI, or container device-runtime fidelity. Unknown health is never
inferred from Node Ready, capacity, or resource-name spelling.
