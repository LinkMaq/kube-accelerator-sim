# 中文

## kube-accelerator-sim v0.1.0

这是 kube-accelerator-sim 的首个正式版本。它面向没有物理加速卡的
Kubernetes 平台开发和测试环境，在用户明确指定的已有集群中模拟控制面可见的
加速器容量、健康度、节点分布和调度信号。

### 主要能力

- 支持 Kubernetes 1.30–1.36 的 scalar extended-resource 调度模拟。
- 支持 Kubernetes 1.34–1.36 的稳定 `resource.k8s.io/v1` DRA 控制面模拟。
- 提供 17 个可选供应商生态的直接可用示例，包括 NVIDIA、AMD、Intel、
  华为昇腾、寒武纪、壁仞、天数智芯、燧原、摩尔线程、沐曦、海光 DCU、
  昆仑芯、AWS Neuron、Google Cloud TPU 等。
- 覆盖整卡、分片、共享设备、虚拟核、显存/内存、设备核和 DRA 等所有当前
  型号兼容、来源可验证的内置资源信号。
- CLI 只向明确选择的已有 Kubernetes 集群提交和管理模拟场景，不管理集群
  生命周期；端到端测试设施可独立创建一次性 kind 集群。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64
  五种原生 `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.1.0`
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.1.0`

### 边界

本项目只模拟 Kubernetes 可见的控制面行为，不提供真实设备访问、加速计算、
厂商驱动或遥测、NUMA 拓扑、CDI 注入，也不声称 CUDA、ROCm、CANN 或容器
设备运行时保真度。昆仑芯示例明确使用社区 HAMi 的 provisional 集成档案，
必须显式接受其公开证据限制；它不冒充厂商默认 Device Plugin 契约。

# English

## kube-accelerator-sim v0.1.0

This is the first production release of kube-accelerator-sim. It targets
Kubernetes platform development and testing without physical accelerators,
projecting control-plane-visible accelerator capacity, health, placement, and
scheduling signals into an explicitly selected existing cluster.

### Highlights

- Scalar extended-resource scheduling simulation for Kubernetes 1.30–1.36.
- Stable `resource.k8s.io/v1` DRA control-plane simulation for Kubernetes
  1.34–1.36.
- Directly applicable examples for 17 selectable accelerator ecosystems,
  including NVIDIA, AMD, Intel, Huawei Ascend, Cambricon, Biren, Iluvatar
  CoreX, Enflame, Moore Threads, MetaX, Hygon DCU, Kunlunxin, AWS Neuron, and
  Google Cloud TPU.
- Coverage for every currently model-compatible, source-backed bundled
  resource signal: whole devices, partitions, shared devices, virtual cores,
  memory, device cores, and DRA.
- The CLI submits and manages Scenarios only in an explicitly selected
  existing Kubernetes cluster. It never manages cluster lifecycle; the E2E
  harness may independently create disposable kind clusters.

### Artifacts

- GitHub Release: five native `kasim` CLI archives for Linux amd64/arm64,
  macOS amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence,
  and a Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.1.0`
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.1.0`

### Boundaries

The project simulates Kubernetes-visible control-plane behavior only. It does
not provide device access, accelerator computation, vendor drivers or
telemetry, NUMA topology, CDI injection, or CUDA, ROCm, CANN, and container
device-runtime fidelity. The Kunlunxin example explicitly uses a provisional
community HAMi integration profile and requires acceptance of its
public-evidence limitations; it is not presented as a vendor-default Device
Plugin contract.
