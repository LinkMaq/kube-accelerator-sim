# 中文

## kube-accelerator-sim v0.5.3

v0.5.3 完善逐设备模拟遥测契约，并正式启用海光 DCU 原始指标。所有已验证厂商的
逐设备时序现在都具备稳定的 `node`、`device`、`model`、`uuid` 和 `vendor`
身份层；厂商已经定义同名 label 时保留其原生值。模拟器继续只生成来源可追溯的
厂商指标，不生成 `rune_accelerator_*`，也不会把非 NVIDIA 设备伪装成 DCGM。

### 主要变化

- 每张加速卡生成独立时序，设备数量与 Synthetic Node 容量一致；同一设备在所有
  family 中使用相同身份，UUID 在 telemetry 进程重启、故障和恢复前后保持稳定。
- 华为 Ascend 增加以下逐设备 family：
  - `npu_chip_info_hbm_used_memory`
  - `npu_chip_info_hbm_total_memory`
  - `npu_chip_info_hbm_utilization`
  - `npu_chip_info_health_status`
  - `npu_chip_info_error_code`
- 华为健康状态保留 npu-exporter 原生约定：`1=健康`、`0=故障`；错误码在健康时
  为零、故障时为非零。`vdie_id` 保持原生虚拟 die 语义，稳定设备 UUID 由独立的
  `uuid` label 提供。
- 海光 DCU 档案从 unavailable 升级为 verified，为 `hygon-k100-ai` 的每张设备
  生成以下 DCU-Exporter 原始 family：
  - `dcu_utilizationrate`
  - `dcu_usedmemory_bytes`
  - `dcu_memorycap_bytes`
  - `dcu_memory_remaining`
  - `dcu_power_usage`
  - `dcu_temp`
  - `dcu_ce_count`
  - `dcu_ue_count`
- 海光指标保留 `device_id`、`minor_number`、`name`、`node`、
  `pcieBus_number` 及 exporter 工作负载 label；模拟器不会伪造不存在的
  `dcu_health` 或物理设备显存百分比 family。健康状态和显存使用率由监控规则或
  消费端基于原始错误计数及显存值推导。
- 八卡池确定性覆盖空闲、持续任务、显存高负载和突发任务状态。使用率、功耗、温度
  和显存具备基本相关性；故障设备同步降低活动并产生非零错误信号，恢复后重新回到
  健康状态。
- 已用显存、剩余显存和总显存保持等式，显存使用率与已用量/总量一致；使用率限制在
  `0–100`。15 秒采样周期和 ServiceMonitor 交付方式保持不变。
- Telemetry Catalog 更新为 `2026-08-12.1`，固定摘要为
  `sha256:40e52b3a86f7df9be9ccd4bddca7cca1e35f819b05fcfa0aef2aa3a2e9df47b0`。
  Telemetry 公共表面版本升级为 `v1alpha5`。
- 规范、ADR、来源研究、中英文运维文档、验收 PromQL、Chart 注解和发布输入已同步。

### 升级说明

该版本不会更改 Scenario CRD、调度资源、Kubernetes 集群生命周期或支持范围；仍支持
Kubernetes 1.30–1.36。新增身份 label 会改变逐设备 Prometheus series 的 label
集合，依赖完整 label 匹配的 recording rule、告警和看板应改为按
`(node, device, model, uuid, vendor)` 关联。

升级 Chart 后，现有华为节点会自动出现新增的 HBM、健康和错误 family；海光节点会
开始生成 DCU-Exporter family。海光健康和显存使用率仍应在监控规则或后端统一计算，
不要依赖模拟器提供非原生聚合指标。集中式 telemetry Pod 的工作负载 label 保持为空，
不能把它误判为实际设备任务。

### 发布产物

  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.3`，同一最小
  运行时镜像包含 `/kasim-controller` 与 `/kasim-telemetry`。
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.5.3`。

# English

## kube-accelerator-sim v0.5.3

v0.5.3 completes the per-device simulated telemetry contract and enables
source-backed Hygon DCU metrics. Every per-device series from a verified vendor
now exposes stable `node`, `device`, `model`, `uuid`, and `vendor` identity.
An exporter-native value wins when the vendor already defines the same label.
The simulator continues to emit only source-backed vendor families: it does
not emit `rune_accelerator_*` and never disguises non-NVIDIA devices as DCGM.

### Highlights

- Every accelerator has an independent series and device count matches the
  Synthetic Node capacity. Identity is consistent across all families, and
  UUIDs survive telemetry-process restarts, faults, and recovery.
- Huawei Ascend adds these per-device families:
  - `npu_chip_info_hbm_used_memory`
  - `npu_chip_info_hbm_total_memory`
  - `npu_chip_info_hbm_utilization`
  - `npu_chip_info_health_status`
  - `npu_chip_info_error_code`
- Huawei health retains the native npu-exporter convention: `1=healthy` and
  `0=faulty`; the error code is zero while healthy and non-zero while faulty.
  Native `vdie_id` retains its virtual-die meaning, while the separate `uuid`
  label carries the stable device UUID.
- The Hygon DCU profile advances from unavailable to verified and emits these
  DCU-Exporter families for every `hygon-k100-ai` device:
  - `dcu_utilizationrate`
  - `dcu_usedmemory_bytes`
  - `dcu_memorycap_bytes`
  - `dcu_memory_remaining`
  - `dcu_power_usage`
  - `dcu_temp`
  - `dcu_ce_count`
  - `dcu_ue_count`
- Hygon metrics retain `device_id`, `minor_number`, `name`, `node`,
  `pcieBus_number`, and exporter workload labels. Kasim does not invent a
  `dcu_health` or physical-device memory-percentage family. Monitoring rules or
  consumers derive health and memory percentage from raw error counters and
  memory values.
- Eight-device pools deterministically cover idle, sustained-work,
  memory-heavy, and bursty states. Utilization, power, temperature, and memory
  are correlated; faulty devices reduce activity and expose non-zero errors,
  then return to healthy behavior after recovery.
- Used, remaining, and total memory preserve their arithmetic invariant;
  memory percentage matches used divided by total, and utilization stays in
  `0–100`. The 15-second sampling interval and ServiceMonitor delivery remain
  unchanged.
- The Telemetry Catalog advances to `2026-08-12.1`, pinned at
  `sha256:40e52b3a86f7df9be9ccd4bddca7cca1e35f819b05fcfa0aef2aa3a2e9df47b0`.
  The telemetry public surface advances to `v1alpha5`.
- The specification, ADR, source research, English and Chinese operator docs,
  acceptance PromQL, Chart annotations, and release inputs are synchronized.

### Upgrade notes

This release does not change the Scenario CRD, scheduling resources,
Kubernetes cluster lifecycle, or support range. Kubernetes 1.30–1.36 remains
supported. The new identity labels change each per-device Prometheus series'
label set. Recording rules, alerts, and dashboards that rely on complete label
matching should join on `(node, device, model, uuid, vendor)`.

After upgrading the Chart, existing Huawei nodes automatically expose the new
HBM, health, and error families, while Hygon nodes begin emitting the
DCU-Exporter families. Hygon health and memory percentage remain downstream
calculations rather than invented native metrics. Workload labels on the
centralized telemetry Pod remain empty and must not be interpreted as a real
device workload.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and a
  Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.3`; the same
  minimal runtime image contains `/kasim-controller` and `/kasim-telemetry`.
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.5.3`.
