# 中文

## kube-accelerator-sim v0.6.1

v0.6.1 将节点发现标签扩展为完整的 36 标签 `nvidia.com/*` 集合，与 GPU Operator
管理节点实际携带的标签集对齐（仅缺 `gfd.timestamp` 与 `gpu.machine`）。新增
CUDA 驱动/CUDA runtime 版本标签、MIG/vGPU/MPS 能力标签、共享与副本标签以及
`gpu.deploy.*` operator 组件状态标签；CUDA runtime 锚定最新 GA 版本 13.3.1。

### 主要变化

- 新增逐型号硬件事实标签：`gpu.mode`（数据中心板为 `compute`）与
  `mig.capable`（除 L40S 外全部为 `true`）。
- 新增契约级派生静态标签（27 个）：CUDA 驱动版本双拼写
  （`cuda.driver-version.full/major/minor/revision` 与已废弃的
  `cuda.driver.major/minor/rev`，锚定 `580.126.16`，与 DCGM 遥测共享驱动
  证据）；CUDA runtime 双拼写（`cuda.runtime-version.full/major/minor` 与
  已废弃的 `cuda.runtime.major/minor`，锚定最新 CUDA GA `13.3.1`）；
  `mig.strategy=single`、`gpu.replicas=1`、`gpu.sharing-strategy=none`、
  `mps.capable=false`、`vgpu.present=false`、`gpu-driver-upgrade-state=
  upgrade-done` 以及 9 个 `gpu.deploy.*` 组件状态（`nvsm` 为空值）。
- 静态派生标签允许空值：GFD 本身会为未部署组件输出空值标签
  （如 `gpu.deploy.nvsm`）；Schema、目录校验、投影与集群写入链路同步放宽。
- NVIDIA 目录升级为 `2026-09-05`，摘要
  `sha256:f4804d5fa2c0e6cd78c0d7cda23aacf653626e81ad64fa33f656ba3e9a9cb8db`；
  Chart 注解与发布输入同步。
- 有意排除项收敛为 `gfd.timestamp`（破坏 Snapshot 确定性）与
  `gpu.machine`（主机特定）两项。
- 运维文档（中英文）与 ADR 0011 同步更新完整标签表。

### 升级说明

该版本不更改 Scenario CRD、调度资源、Kubernetes 集群生命周期或支持范围；仍支持
Kubernetes 1.30–1.36。发现标签默认关闭；已开启 `discoveryLabels` 的场景在
升级后重新提交即可获得完整 36 标签集。CUDA runtime 值为目录锚定的最新 GA
版本，升级目录修订版即可更新。

# English

## kube-accelerator-sim v0.6.1

v0.6.1 extends node discovery labels to the complete 36-label `nvidia.com/*`
set that GPU Operator-managed nodes actually carry (only `gfd.timestamp` and
`gpu.machine` remain excluded). It adds CUDA driver and CUDA runtime version
labels, MIG/vGPU/MPS capability labels, sharing and replica labels, and the
`gpu.deploy.*` operator component states; the CUDA runtime is pinned to the
latest GA release 13.3.1.

### Highlights

- New per-model hardware-fact labels: `gpu.mode` (`compute` for data-center
  boards) and `mig.capable` (`true` for every model except L40S).
- New contract-derived static labels (27): CUDA driver versions in both GFD
  spellings (`cuda.driver-version.full/major/minor/revision` and the
  deprecated `cuda.driver.major/minor/rev`, pinned to `580.126.16` shared
  with DCGM telemetry evidence); CUDA runtime versions in both spellings
  (`cuda.runtime-version.full/major/minor` and the deprecated
  `cuda.runtime.major/minor`, pinned to the latest CUDA GA `13.3.1`);
  `mig.strategy=single`, `gpu.replicas=1`, `gpu.sharing-strategy=none`,
  `mps.capable=false`, `vgpu.present=false`, `gpu-driver-upgrade-state=
  upgrade-done`, and the nine `gpu.deploy.*` component states (with an empty
  `nvsm`).
- Static derived labels may now be empty because GFD itself emits empty
  values for undeployed components (for example `gpu.deploy.nvsm`); the
  schema, catalog validation, projection, and cluster write path all relax
  accordingly.
- The NVIDIA catalog moves to `2026-09-05` with digest
  `sha256:f4804d5fa2c0e6cd78c0d7cda23aacf653626e81ad64fa33f656ba3e9a9cb8db`;
  Chart annotations and release inputs are synchronized.
- The deliberate exclusion list shrinks to `gfd.timestamp` (Snapshot
  determinism) and `gpu.machine` (host-specific).
- Operator documentation (English and Chinese) and ADR 0011 now document the
  complete label table.

### Upgrade notes

No Scenario CRD, scheduling resource, cluster lifecycle, or compatibility
range changes; Kubernetes 1.30–1.36 remains supported. Discovery labels stay
off by default; resubmit scenarios that enable `discoveryLabels` to receive
the full 36-label set. The CUDA runtime value is pinned per catalog revision
to the latest CUDA GA release and updates with the catalog.
