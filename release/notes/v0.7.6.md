# 中文

## kube-accelerator-sim v0.7.6

v0.7.6 增加一台可调度的华为 Atlas A2 单机 8 卡节点，并把昇腾遥测对到当前 Rune `ascend-npu` 规则。

- 示例是 `examples/huawei-atlas-a2.yaml`：一台节点 8 张整卡，资源 `huawei.com/Ascend910`。节点带 `node.kubernetes.io/npu.chip.name=910B` 和 `servertype=Ascend910B-20`。HBM 沿用档案默认 65536 MiB，不是实测容量。
- 每张芯片的 `vdie_id` 是稳定 UUID，供 `ascend-npu` 作为 `device_id`。新增 `npu_chip_info_power_limit`，取值是档案功耗上限。
- Chart 在命名空间 `npu-exporter` 运行第二个 telemetry 进程，Pod 标签 `app=npu-exporter`，端口名 `http`。样本的 `node` 标签是合成节点，规则优先使用它。
- Profile Catalog 仍是 `2026-11-23.3`。Telemetry Catalog 修订为 `2026-11-23.4`，摘要 `sha256:83ace78871d43d55c59e2dc64f1a3e8669f4eb5d68a66c28b239711b04a8fafe`。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.7.6`。Helm Chart：`kasim-runtime` `0.7.6`。已发布的 `0.7.5` 标签保持不变。

# English

## kube-accelerator-sim v0.7.6

v0.7.6 adds a schedulable Huawei Atlas A2 node with eight physical cards and aligns Ascend telemetry with the current Rune `ascend-npu` rule.

- `examples/huawei-atlas-a2.yaml` projects one node with eight whole cards on `huawei.com/Ascend910`. The node carries `node.kubernetes.io/npu.chip.name=910B` and `servertype=Ascend910B-20`. HBM stays on the profile default of 65536 MiB and is not a measured capacity.
- Each chip's `vdie_id` is a stable UUID, which `ascend-npu` reads as `device_id`. `npu_chip_info_power_limit` is the profile power maximum.
- The chart runs a second telemetry process in namespace `npu-exporter`, with Pod label `app=npu-exporter` and port name `http`. The sample `node` label is the Synthetic Node, and the rule prefers it.
- The Profile Catalog remains `2026-11-23.3`. The Telemetry Catalog revision is `2026-11-23.4`, digest `sha256:83ace78871d43d55c59e2dc64f1a3e8669f4eb5d68a66c28b239711b04a8fafe`.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.7.6`. Helm chart: `kasim-runtime` `0.7.6`. The published `0.7.5` tag is unchanged.
