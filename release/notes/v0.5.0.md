# 中文

## kube-accelerator-sim v0.5.0

v0.5.0 将模拟遥测升级为原厂 exporter 契约优先：每条厂商指标现在使用经过
证据审计的原厂指标名、`HELP`、`TYPE` 和完整 label key 集合，不再向原厂 family
注入 Kasim 私有标签或通用兼容标签。模拟设备仍由集中式只读 telemetry Pod 生成，
但指标结构可以直接用于验证现有 PromQL、看板、告警规则和平台适配逻辑。

### 主要变化

- 遥测目录升级到 `v1alpha2`，修订为 `2026-08-10`，固定摘要为
  `sha256:226638cfe275c8c83f88b06a3d11b4c9bad3e5df9578da4eed392f64aed3a0f4`。
- 审计并固定 71 个 NVIDIA、AMD、Intel、华为昇腾、寒武纪、天数智芯、燧原、
  Furiosa 和 InfiniBand exporter family 的原厂 `HELP`、Prometheus 类型及 label。
- NVIDIA DCGM 覆盖 20 个常用 family，包括时钟、温度、功耗、能耗、利用率、
  显存、XID、行重映射、NVLink 和 vGPU License；完整回归样例与用户提供的
  DCGM exposition 契约逐项一致。
- 原厂 family 不再携带额外的 `kasim_*` 或通用 `node`。设备节点身份使用 exporter
  自己的 key，例如 DCGM `Hostname`、AMD `hostname`、寒武纪 `node`、天数智芯
  `node_name` 和燧原 `host`。
- Kasim 来源、Scenario、Synthetic Node、档案和可用性继续由独立的
  `kasim_telemetry_*` 诊断 family 表达，不污染原厂序列。
- 数值生成仍为 15 秒确定性快照；利用率、显存、功耗、温度、时钟和流量共享关联
  负载，counter 单调递增，不健康设备使用对应 exporter 的健康表达。
- 更新 Helm、CLI、双语在线文档和发布契约到 `0.5.0`。ServiceMonitor 仍是显式
  开关，可保留现有 Helm 配置。

### 不兼容变化与迁移

如果下游查询依赖 v0.4.1 自动添加的 `node` 或 `kasim_*` label，需要改为读取对应
exporter 的原生节点 label。不要通过 `kube_pod_info` 把集中式 telemetry Pod 所在
的真实节点补到设备序列。需要 Kasim 归属信息时，应单独查询 `kasim_telemetry_*`
family，并在应用层按 Scenario/Synthetic Node 关系组合结果。

本次升级不修改 Scenario 传输格式、CRD、调度资源名、现有 Scenario Instance 或
Kubernetes 集群。支持范围仍为 Kubernetes 1.30–1.36，升级 Kasim 不要求升级集群。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64 原生
  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.0`，同一个最小
  运行时镜像内包含 `/kasim-controller` 与 `/kasim-telemetry`。
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.5.0`。

# English

## kube-accelerator-sim v0.5.0

v0.5.0 makes simulated telemetry exporter-contract-first. Every vendor family
now uses its evidence-audited metric name, `HELP`, `TYPE`, and complete native
label-key set. Kasim-private and generic compatibility labels are no longer
injected into vendor families. A centralized read-only telemetry Pod still
generates the simulated values, while the resulting schemas can exercise
existing PromQL, dashboards, alert rules, and platform adapters directly.

### Highlights

- Upgraded the Telemetry Catalog to `v1alpha2`, revision `2026-08-10`, pinned
  at `sha256:226638cfe275c8c83f88b06a3d11b4c9bad3e5df9578da4eed392f64aed3a0f4`.
- Audited and pinned native `HELP`, Prometheus types, and labels for 71 exporter
  families across NVIDIA, AMD, Intel, Huawei Ascend, Cambricon, Iluvatar,
  Enflame, Furiosa, and InfiniBand.
- NVIDIA DCGM now covers 20 commonly consumed families for clocks,
  temperatures, power, energy, utilization, framebuffer memory, XID, row
  remapping, NVLink, and vGPU licensing. The full regression fixture matches
  the supplied DCGM exposition contract field by field.
- Vendor families no longer carry added `kasim_*` or generic `node` labels.
  Device ownership uses the exporter's native key, such as DCGM `Hostname`, AMD
  `hostname`, Cambricon `node`, Iluvatar `node_name`, or Enflame `host`.
- Separate `kasim_telemetry_*` diagnostic families retain Kasim provenance,
  Scenario, Synthetic Node, profile, and availability data without changing
  vendor series.
- Values remain deterministic 15-second snapshots. Utilization, memory, power,
  temperature, clocks, and traffic share a correlated load state; counters are
  monotonic and unhealthy devices use exporter-specific health semantics.
- Synchronized Helm, CLI, bilingual online documentation, and release
  contracts to `0.5.0`. ServiceMonitor remains an explicit option and existing
  Helm settings can be preserved.

### Breaking change and migration

Queries that depended on the extra `node` or `kasim_*` labels added in v0.4.1
must read the corresponding exporter's native Node label instead. Do not use
`kube_pod_info` to attach the real Node hosting the centralized telemetry Pod
to device series. Query the separate `kasim_telemetry_*` families when Kasim
provenance is required, and combine Scenario/Synthetic Node relationships at
the application layer.

This upgrade does not change the Scenario transport, CRDs, scheduling resource
names, existing Scenario Instances, or the Kubernetes cluster. The supported
range remains Kubernetes 1.30–1.36, and upgrading Kasim does not require a
cluster upgrade.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and a
  Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.0`; the same
  minimal runtime image contains `/kasim-controller` and `/kasim-telemetry`.
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.5.0`.
