# 中文

## kube-accelerator-sim v0.2.0

v0.2.0 增加了本地只读集群清单和辅助设备调度信号，让平台开发者可以在没有
物理加速卡或网卡的环境中同时验证资源发布、调度适配和清单展示。CLI 仍然只
连接用户显式指定的已有 Kubernetes 集群，不负责集群生命周期。

### 主要变化

- 新增 `kasim ui`。一条命令即可在 `127.0.0.1` 启动内嵌的中英文设备与信号
  账本，显著区分 Kasim Synthetic Node 和真实节点。
- 首页直接展示准确的标量资源名、原生 DRA `(driver, pool, device)` 标识、
  厂商/型号证据、容量、可分配量、Pod 请求、ResourceClaim 分配阶段和健康
  信息缺口。
- 新增 RDMA Shared Device Plugin 与 SR-IOV Network Device Plugin 的
  Auxiliary Device Pool 契约和可运行示例。可配置资源名必须由 Scenario 显式
  提供，辅助数量只代表调度令牌。
- 清单源采用独立的 list/watch、分页、书签、410 重列、watch 禁止时轮询、
  有界随机退避、陈旧数据标记和慢消费者合并策略。
- Catalog 升级到 `v1alpha2` / `2026-08-03`，同时保留原有加速卡 Profile
  内容摘要；Kubernetes 兼容范围仍为 1.30–1.36，稳定 DRA 仍为 1.34–1.36。
- 更新英文/中文在线文档、操作 Skill、场景示例、CRD 状态字段与发布验证。

### 本地 UI 安全边界

每次 `kasim ui` 启动都会生成新的 256 位临时访问能力，并只把它放在 URL
fragment 中。服务只监听回环地址，只接受 `GET`/`HEAD`，没有写接口、远程绑定、
第三方资源或宽松 CORS。访问 URL 应按临时密钥处理。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64
  原生 `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- 发布收据逐平台记录 UI 原始/gzip 资源大小和压缩二进制增量，并强制执行
  256 KiB、96 KiB 和 1 MiB 上限。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.2.0`
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.2.0`

### 真实性边界

Kasim 只模拟 Kubernetes 控制平面可见行为。它不提供物理设备访问、加速计算、
厂商驱动、遥测、NUMA、CDI 或容器设备运行时保真度。RDMA/SR-IOV 辅助令牌不
证明物理网卡、链路、CNI、网络、GPUDirect 或数据通路可用。未知健康信息不会
从 Node Ready、容量或资源名推断。

# English

## kube-accelerator-sim v0.2.0

v0.2.0 adds a local read-only cluster inventory and auxiliary scheduling
signals so platform developers can validate resource publication, scheduling
integration, and inventory presentation without physical accelerators or
NICs. The CLI still targets only an explicitly selected existing Kubernetes
cluster and does not own cluster lifecycle.

### Highlights

- Added `kasim ui`, an embedded bilingual device and signal ledger served on
  `127.0.0.1`, with Kasim Synthetic Nodes clearly separated from other Nodes.
- The home page shows exact scalar resource names, native DRA
  `(driver, pool, device)` identities, vendor/model evidence, capacity,
  allocatable quantity, Pod requests, ResourceClaim allocation phases, and
  explicit health gaps.
- Added Auxiliary Device Pool contracts and runnable examples for the RDMA
  Shared Device Plugin and SR-IOV Network Device Plugin. Configurable resource
  names must be supplied by the Scenario, and counts are scheduling tokens.
- Inventory sources use independent paginated list/watch loops, bookmarks,
  410 relists, polling fallback when watch is forbidden, bounded jitter,
  stale-state reporting, and slow-consumer coalescing.
- Advanced the catalog to `v1alpha2` / `2026-08-03` while retaining existing
  accelerator Profile content digests. Kubernetes remains bounded to
  1.30–1.36, with stable DRA on 1.34–1.36.
- Updated English and Chinese documentation, the repository operation Skill,
  examples, CRD status fields, and release verification.

### Local UI security boundary

Each `kasim ui` launch creates a new 256-bit ephemeral capability and places
it only in the URL fragment. The server is loopback-only, accepts only
`GET`/`HEAD`, and has no mutation route, remote binding, third-party asset, or
permissive CORS. Treat the access URL as a temporary secret.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and
  a Sigstore signature.
- The release receipt records raw/gzip UI asset sizes and compressed binary
  deltas for every platform, enforcing 256 KiB, 96 KiB, and 1 MiB limits.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.2.0`
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.2.0`

### Truth boundaries

Kasim simulates Kubernetes-visible control-plane behavior only. It does not
provide physical device access, accelerator computation, vendor drivers,
telemetry, NUMA, CDI, or container device-runtime fidelity. RDMA/SR-IOV
auxiliary tokens do not prove a NIC, link, CNI, fabric, GPUDirect path, or
working data plane. Unknown health is never inferred from Node Ready,
capacity, or resource-name spelling.
