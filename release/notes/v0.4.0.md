# 中文

## kube-accelerator-sim v0.4.0

v0.4.0 为每个由 Kasim 准确归属的模拟节点和设备增加 Prometheus 格式遥测。
新能力通过独立、只读的 `kasim-telemetry` 进程提供，默认随运行时 Chart 安装；
现有 Scenario 文件和 `kasim` CLI 生命周期保持不变。

### 主要变化

- 新增来源锁定的遥测目录。已验证并启用 NVIDIA DCGM、AMD Device Metrics
  Exporter、Intel XPU Manager、华为 Ascend npu-exporter、寒武纪
  mlu-exporter、天数智芯 ix-exporter、燧原 gcu-exporter、Furiosa exporter
  与 node_exporter InfiniBand 指标 family。
- 指标保留原厂 family 名和原生 label key，并额外加入
  `kasim_simulated="true"`、节点、实例、档案、型号和设备身份标签，避免模拟值
  与物理测量混淆。
- 利用率、显存、功耗、温度、频率和流量由同一个确定性负载状态关联生成；同一
  15 秒时间桶内重复抓取和进程重启保持一致，counter 从固定模拟 epoch 单调增长。
- 每个归属节点都提供 `kasim_telemetry_node_info`；证据不足的厂商档案通过
  `kasim_telemetry_device_contract_available` 明确标记，而不会猜测原厂指标名。
- Prometheus 抓取只读取不可变内存快照，不在请求路径访问 Kubernetes API。
  数据源失败时保留最后成功快照至 45 秒，随后移除原厂 series 并让 readiness
  失败。
- 默认 ClusterIP Service 使用标准 Prometheus 抓取注解；也可显式启用可选的
  ServiceMonitor。两种发现方式不会同时生效。
- 独立 ServiceAccount 只允许 `get/list/watch` Scenario Instance 和 Node；
  telemetry Pod 与其他运行时组件一样只能调度到真实节点。
- 增加 1,000 节点、8,000 设备参考规模测试、Prometheus 文本解析测试、数值
  不变量测试、失效/陈旧边界测试、Helm 安全与 RBAC 契约以及中英文在线文档。
- 修复已绑定 Pod 同时包含 `cpu: 100m` 与扩展资源时的协调错误：协调器现在只按
  当前投射资源计算设备请求，仍会拒绝扩展资源本身的非整数请求。
- 操作 Skill 的 `doctor.py` 现在可完整解析较大的 Deployment 列表，再对回执输出
  做有标记的截断，避免运行时组件较多时误报。

### 真实性边界

这些值用于验证 Prometheus 采集、看板、告警和平台适配，不是物理板卡、驱动或
原厂 exporter 的读数，不能用于容量规划、性能评测、功耗/温度规划或硬件故障
诊断。调度档案可用不代表遥测契约可用；缺少可固定、可复核一手证据的厂商保持
`provisional` 或 `unavailable`。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64 原生
  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.4.0`，同一个最小
  运行时镜像内包含 `/kasim-controller` 与 `/kasim-telemetry`。
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.4.0`。

### 兼容性

Kubernetes 支持范围保持为 1.30–1.36；`scheduling` 覆盖整个范围，稳定 DRA
控制平面模拟为 1.34–1.36。升级不会修改已有 Scenario 传输格式。

# English

## kube-accelerator-sim v0.4.0

v0.4.0 adds Prometheus-format telemetry for every simulated Node and device
that Kasim owns exactly. A separate read-only `kasim-telemetry` process ships
with the runtime chart by default; existing Scenario files and the `kasim` CLI
lifecycle remain unchanged.

### Highlights

- Added a source-locked telemetry catalog. Verified native families are enabled
  for NVIDIA DCGM, AMD Device Metrics Exporter, Intel XPU Manager, Huawei Ascend
  npu-exporter, Cambricon mlu-exporter, Iluvatar ix-exporter, Enflame
  gcu-exporter, Furiosa metrics exporter, and node_exporter InfiniBand metrics.
- Native family names and label keys are retained. Additional provenance labels,
  including `kasim_simulated="true"`, identify the Scenario, Node, profile,
  model, and device so synthetic values cannot be mistaken for hardware reads.
- Utilization, memory, power, temperature, clock, and traffic values derive from
  one deterministic correlated load state. Scrapes are stable within each
  15-second bucket and across restarts; counters increase from a fixed simulator
  epoch.
- Every owned Node exposes `kasim_telemetry_node_info`. Profiles without enough
  evidence are identified by `kasim_telemetry_device_contract_available`
  without inventing vendor-native metric names.
- Prometheus scrapes read only an immutable in-memory snapshot and perform no
  Kubernetes API I/O. Source failures retain the last successful snapshot for
  45 seconds, then remove native series and fail readiness.
- A ClusterIP Service uses standard Prometheus scrape annotations by default;
  an optional ServiceMonitor is available and the two discovery modes are
  mutually exclusive.
- A dedicated ServiceAccount can only `get`, `list`, and `watch` Scenario
  Instances and Nodes. The telemetry Pod shares the runtime's hard placement
  boundary on real Nodes.
- Added a 1,000-Node/8,000-device reference-scale test, Prometheus exposition
  parsing, value-invariant and stale-state tests, Helm/RBAC contracts, and
  bilingual public documentation.
- Fixed reconciliation for bound Pods that combine `cpu: 100m` with extended
  resources: only projected device resources are parsed for device accounting,
  while non-integer extended-resource requests still fail closed.
- Updated the operation Skill's `doctor.py` to parse larger Deployment lists
  before applying a marked receipt-output truncation, preventing false runtime
  inventory failures as more components are installed.

### Fidelity boundary

These values support Prometheus ingestion, dashboard, alert, and platform
adapter tests. They are not physical accelerator, driver, or vendor exporter
measurements and must not be used for capacity planning, benchmarking, thermal
or power planning, or hardware diagnosis. Scheduling support does not imply a
verified telemetry contract; vendors without pinned reviewable primary evidence
remain `provisional` or `unavailable`.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and a
  Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.4.0`; the same
  minimal runtime image contains `/kasim-controller` and `/kasim-telemetry`.
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.4.0`.

### Compatibility

The supported Kubernetes range remains 1.30–1.36. Scheduling mode spans the
whole range, while stable DRA control-plane simulation spans 1.34–1.36. This
upgrade does not change the Scenario transport format.
