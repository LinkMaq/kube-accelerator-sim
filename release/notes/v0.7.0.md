# 中文

## kube-accelerator-sim v0.7.0

v0.7.0 新增阿里云真武 PPU（Parallel Processing Unit）的模拟契约，来源为阿里云
ACK 官方 `ack-ppu-device-plugin` 组件文档与灵骏节点池 PPU 使用指南。PPU 的
Kubernetes 资源名与节点标签全部逐字取自第一方文档，不从模型 ID 反推，也不为
缺少公开契约的 exporter 编造指标名。

### 主要变化

- 新增 `alibaba-ppu` profile，class 为 `verified`，提供 `device-plugin`
  extended-resource 契约：
  - 整卡资源 `alibabacloud.com/ppu`（unit `device`）
  - 两个代表性 MIG 分区资源 `alibabacloud.com/ppu-4u.4g48gb` 与
    `alibabacloud.com/ppu-16u.4g48gb`（unit `partition`）。插件文档共枚举
    15 个分区资源，本次登记其中两个以代表分区模式并控制维护面；未登记的
    分区不声明，也不从已登记项推导。
- 型号：`alibaba-ppu-zw810e`（PPU-ZW810E）与 `alibaba-ppu-m890p`（M890P，
  插件 1.4.0 显式声明全面支持）。
- 身份信号：契约声明 `aliyun.accelerator/xpu_type`、
  `aliyun.accelerator/ppu_name`、`aliyun.accelerator/ppu_count`、
  `aliyun.accelerator/ppu_mem` 四个 node-label 身份键。
- 契约能力：`health`、`topology`、`partitioning` 记为 `verified`（插件文档
  明确声明上报健康状态、机内拓扑感知调度与 MIG 调度）；`sharing` 记为
  `not-public`，因为文档未描述共享设备路径。
- `providerScope` 为 `alibaba-cloud-ack`：该插件是 ACK 托管组件，不是可在
  任意集群自行安装的上游通用插件，与 `aws-ec2-eks`、`google-gke` 同类。
- 模拟遥测档案登记为 `unavailable`：ACK 确实公开了真武 PPU 指标页，但该页声明
  与开源 DCGM Exporter 指标兼容，因此复用了已由 NVIDIA 契约持有的
  `DCGM_FI_*` 族名。遥测目录只允许一个族归属，且该页未给出精确的 `HELP`
  文本与完整标签模式、也没有不可变修订锚点。本版因此不声明任何 metric
  family，PPU 场景只报 `kasim_telemetry_device_contract_available=0`。Kasim
  不会为了让示例看起来被覆盖而由调度资源名派生指标名。
- 示例新增 `examples/vendors/alibaba-ppu.yaml`（整卡 8 卡形态），并在
  `examples/signals/extended-resource-variants.yaml` 新增
  `alibaba-ppu-partitions` 节点组覆盖两个分区资源；`examples/README.md` 的
  厂商表与分区信号表同步更新。
- 证据锚点：`https://help.aliyun.com/zh/ack/product-overview/ack-ppu-device-plugin`
  （revision `v1.4.0-8a13b6d4-topology-aliyun`，2026-08-05 首次全量发布）与
  `https://www.alibabacloud.com/help/zh/ack/ack-managed-and-ack-dedicated/user-guide/use-ppu-in-lingjun-node-pool`
  （节点标签样值）。两目录 revision 升级为 `2026-09-16.1`。
- Profile Catalog 摘要更新为
  `sha256:d2139ae426ce2c3de02c9103752640d418db53092578e033cbe20420882375dc`；
  Telemetry Catalog 摘要更新为
  `sha256:80157a7e1720cb5e064a6dbd5e444845d540e8cf43854156a838dec43737786e`。
  Chart 注解与发布输入同步。
- 中英文运维文档（`profile-evidence`、`simulated-vendor-telemetry`、
  `node-discovery-labels`）与示例索引同步更新。
- Bump product and chart version to 0.7.0。

### 升级说明

该版本不更改 Scenario CRD、调度资源或 Kubernetes 支持范围；仍支持 Kubernetes
1.30–1.36。

**新增 profile 会改变目录 revision。** 既有场景实例钉住提交时的 profile
revision 与 digest，因此升级 runtime 前必须先删除所有既有场景实例，在空集群上
完成 `helm upgrade`，再用新 CLI 重新提交。若直接升级，旧实例的 telemetry 编译
会失败，`helm --wait` 会因 telemetry Deployment 不就绪而超时。

PPU 场景不产生厂商指标序列；这是「无公开 exporter 契约」的如实表达，不是缺陷。
需要 PPU 容量与调度行为验证时请使用调度层面的判据，不要期待
`alibabacloud.com/ppu` 相关的 Prometheus 序列。

# English

## kube-accelerator-sim v0.7.0

v0.7.0 adds the simulation contract for Alibaba Cloud Zhenwu PPU (Parallel
Processing Unit), sourced from the official ACK `ack-ppu-device-plugin`
component documentation and the Lingjun node pool PPU guide. Every PPU
Kubernetes resource name and node label is taken verbatim from first-party
documentation; nothing is reverse-engineered from a model ID, and no metric
name is invented for an exporter without a public contract.

### Highlights

- A new `alibaba-ppu` profile, class `verified`, provides one `device-plugin`
  extended-resource contract:
  - Whole-device resource `alibabacloud.com/ppu` (unit `device`).
  - Two representative MIG partition resources,
    `alibabacloud.com/ppu-4u.4g48gb` and `alibabacloud.com/ppu-16u.4g48gb`
    (unit `partition`). The plugin documentation enumerates 15 partition
    resources; two are recorded here to represent the partition mode while
    keeping the maintenance surface bounded. Unrecorded partitions are not
    declared and are not derived from recorded ones.
- Models: `alibaba-ppu-zw810e` (PPU-ZW810E) and `alibaba-ppu-m890p` (M890P,
  explicitly fully supported as of plugin 1.4.0).
- Identity signals: the contract declares the `aliyun.accelerator/xpu_type`,
  `aliyun.accelerator/ppu_name`, `aliyun.accelerator/ppu_count`, and
  `aliyun.accelerator/ppu_mem` node-label identity keys.
- Contract capabilities: `health`, `topology`, and `partitioning` are
  `verified`, because the plugin documentation explicitly states that it
  reports device health and supports in-node topology-aware and MIG
  scheduling. `sharing` is `not-public` because no shared-device path is
  documented.
- `providerScope` is `alibaba-cloud-ack`: the plugin is an ACK-managed
  component rather than an upstream plugin installable on any cluster, which
  matches the `aws-ec2-eks` and `google-gke` precedent.
- The simulated telemetry profile is recorded as `unavailable`: PPU has no
  public exporter metric contract, so no metric family is declared and PPU
  Scenarios report only `kasim_telemetry_device_contract_available=0`. Kasim
  never derives a metric name from a scheduling resource merely to make an
  example look covered.
- Examples gain `examples/vendors/alibaba-ppu.yaml` (whole-device, eight
  devices) and a new `alibaba-ppu-partitions` Node Group in
  `examples/signals/extended-resource-variants.yaml` covering both partition
  resources; the `examples/README.md` vendor and partition signal tables are
  updated.
- Evidence anchors:
  `https://help.aliyun.com/zh/ack/product-overview/ack-ppu-device-plugin`
  (revision `v1.4.0-8a13b6d4-topology-aliyun`, initial full release on
  2026-08-05) and
  `https://www.alibabacloud.com/help/zh/ack/ack-managed-and-ack-dedicated/user-guide/use-ppu-in-lingjun-node-pool`
  (node label sample values). Both catalog revisions advance to
  `2026-09-16.1`.
- The Profile Catalog digest is now
  `sha256:d2139ae426ce2c3de02c9103752640d418db53092578e033cbe20420882375dc`;
  the Telemetry Catalog digest is now
  `sha256:80157a7e1720cb5e064a6dbd5e444845d540e8cf43854156a838dec43737786e`.
  Chart annotations and release inputs are synchronized.
- English and Chinese operator documentation (`profile-evidence`,
  `simulated-vendor-telemetry`, `node-discovery-labels`) and the examples
  index are synchronized.
- Bump product and chart version to 0.7.0.

### Upgrade notes

This release does not change the Scenario CRD, scheduling resources, or the
Kubernetes support range. Kubernetes 1.30–1.36 remains supported.

**Adding a profile changes the catalog revision.** Existing Scenario Instances
pin the profile revision and digest they were submitted with, so every
existing instance must be deleted before upgrading the runtime, the
`helm upgrade` must run against an empty cluster, and the Scenarios must then
be resubmitted with the new CLI. Upgrading in place fails telemetry
compilation for the pinned revisions and makes `helm --wait` time out while
the telemetry Deployment stays unready.

PPU Scenarios produce no vendor metric series. That is an accurate statement
about a public contract that collides with already-verified family names and
cannot currently be admitted, not a defect. Validate PPU capacity and scheduling
behavior with scheduling-level evidence rather than expecting Prometheus series
for `alibabacloud.com/ppu`.
