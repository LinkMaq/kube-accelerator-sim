# 中文

## kube-accelerator-sim v0.6.0

v0.6.0 新增证据驱动的节点发现标签特性。Synthetic Node 现在可以携带与 NVIDIA
GPU Operator 的 GPU Feature Discovery（GFD）一致的 `nvidia.com/*` 节点标签集，
使工作负载通过 `nodeSelector`/亲和性选择模拟节点时走过与真实 GPU 集群完全相同
的调度路径。所有标签值来自目录逐型号证据，绝不以模型 ID 冒充 vendor 值。

### 主要变化

- Profile Catalog Schema 升级：model 增加可选 `nodeLabels` 逐型号证据值，
  Resource Contract 增加可选 `derivedNodeLabels`（`static` 与
  `pool-total-capacity` 两种派生来源）。
- NVIDIA 目录升级为 `2026-09-04`：10 个可选型号补齐
  `gpu.product`、`gpu.family`、`gpu.compute.major`、`gpu.compute.minor`、
  `gpu.memory` 证据值；证据源固定为
  `NVIDIA/k8s-device-plugin@3c6be400411aad793892e976824910d0880dd3a8` 的 GFD
  文档。
- Scenario 文档增加可选 `node.discoveryLabels` 开关，`apply demo` 快捷方式
  增加 `--discovery-labels`；两者均默认关闭，省略时规范场景字节与摘要保持
  不变，既有场景修订版不受影响。
- 开启后每个 Synthetic Node 获得 `gpu.present`、`gpu.count`、`gpu.product`、
  `gpu.family`、`gpu.compute.major`、`gpu.compute.minor`、`gpu.memory` 七个
  标签；标签纳入 `extended-resources` 保真面，逐节点校验，漂移即失败。
- 多池冲突、跨池值冲突、与 Scenario 提供标签的冲突均编译失败（fail closed）。
- 有意排除：`gfd.timestamp`、`gpu.machine`、`gpu.clique`、MIG 策略标签、
  CUDA runtime 版本标签；不声明驱动、设备文件、CUDA 或真实硬件。
- 新增运维文档（中英文）、ADR 0011、示例
  `examples/discovery-labels.yaml`。
- Profile Catalog 摘要更新为
  `sha256:a8be23853f708ad24f388bf66208ded51435894703d48e773642971d8f93441d`，
  Chart 注解与发布输入同步。

### 升级说明

该版本不更改 Scenario CRD、调度资源、Kubernetes 集群生命周期或支持范围；仍支持
Kubernetes 1.30–1.36。发现标签默认关闭；需要与真实 GPU 集群一致的节点选择语义
时，在 Node Group 上开启 `discoveryLabels` 并重新提交场景。

# English

## kube-accelerator-sim v0.6.0

v0.6.0 introduces evidence-backed node discovery labels. Synthetic Nodes can
now carry the `nvidia.com/*` label set produced by the NVIDIA GPU Operator's
GPU Feature Discovery, so workload nodeSelector and affinity tests exercise
the identical selection path as real GPU clusters. Every value comes from
per-model catalog evidence; model IDs are never substituted for vendor values.

### Highlights

- Profile catalog schema gains optional per-model `nodeLabels` evidence values
  and optional contract `derivedNodeLabels` (`static` and
  `pool-total-capacity`).
- The NVIDIA catalog moves to `2026-09-04`: all ten selectable models now
  carry `gpu.product`, `gpu.family`, `gpu.compute.major`,
  `gpu.compute.minor`, and `gpu.memory` evidence pinned to
  `NVIDIA/k8s-device-plugin@3c6be400411aad793892e976824910d0880dd3a8`.
- Scenario documents gain an optional `node.discoveryLabels` opt-in flag and
  the `apply demo` shortcut gains `--discovery-labels`. Both default to off;
  omitting them preserves canonical bytes and digests, so accepted revisions
  stay immutable.
- When enabled, each Synthetic Node receives `gpu.present`, `gpu.count`,
  `gpu.product`, `gpu.family`, `gpu.compute.major`, `gpu.compute.minor`, and
  `gpu.memory`. Labels join the `extended-resources` fidelity surface and are
  verified per Node.
- Pool, cross-pool, and Scenario-label conflicts fail compilation.
- Deliberately excluded: `gfd.timestamp`, `gpu.machine`, `gpu.clique`, MIG
  strategy labels, and CUDA runtime version labels.
- New operator documentation (English and Chinese), ADR 0011, and the
  `examples/discovery-labels.yaml` example.
- Profile catalog digest is now
  `sha256:a8be23853f708ad24f388bf66208ded51435894703d48e773642971d8f93441d`;
  Chart annotations and release inputs are synchronized.

### Upgrade notes

No Scenario CRD, scheduling resource, cluster lifecycle, or compatibility
range changes; Kubernetes 1.30–1.36 remains supported. Discovery labels are
off by default; enable `discoveryLabels` per Node Group to mirror real
GPU-cluster node selection semantics.
