# 中文

## kube-accelerator-sim v0.4.1

v0.4.1 修复集中式遥测 Pod 与模拟设备所属节点不一致时的节点归属问题。
每条原厂加速卡指标现在都明确携带 `node=<Synthetic Node>`，并与
`Hostname`/`hostname` 和 `kasim_node` 中的模拟节点身份保持一致。

### 主要变化

- 为 NVIDIA、AMD、Intel、华为昇腾、寒武纪、天数智芯、燧原、Furiosa
  等已启用原厂指标 family 的每条设备样本增加 Prometheus 兼容标签
  `node=<Synthetic Node>`，不改变原厂指标名和原生 label key。
- `node` 始终表示设备所属的 Synthetic Node，绝不表示承载集中式
  `kasim-telemetry` Pod 的真实 Kubernetes Node。
- 依赖 `node` 标签的下游 PromQL 不再需要通过 `kube_pod_info` 推导设备归属，
  避免把多个模拟节点的设备错误归到同一真实节点并在资源池匹配时被过滤。
- 增加双层回归验证：快速测试覆盖两个 Synthetic Node 的样本归属；真实 Kind
  兼容性测试验证 telemetry Pod 位于真实节点，而每条 NVIDIA 指标仍指向正确的
  Synthetic Node。
- 同步更新 Helm、CLI、在线中英文文档和发布契约到 `0.4.1`。

### 升级影响

本次升级不修改 Scenario 传输格式、CRD、调度资源名、厂商指标 family、数值模型
或现有 Scenario Instance。Kubernetes 支持范围保持为 1.30–1.36；ServiceMonitor
仍为显式开关，升级时可以保留现有配置。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64 原生
  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.4.1`，同一个最小
  运行时镜像内包含 `/kasim-controller` 与 `/kasim-telemetry`。
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.4.1`。

# English

## kube-accelerator-sim v0.4.1

v0.4.1 fixes device-to-Node attribution when the centralized telemetry Pod
runs on a different Node from the simulated devices it describes. Every
vendor-native accelerator sample now carries `node=<Synthetic Node>`, aligned
with the simulated Node identity in `Hostname`/`hostname` and `kasim_node`.

### Highlights

- Added the Prometheus compatibility label `node=<Synthetic Node>` to every
  device sample in enabled native metric families for NVIDIA, AMD, Intel,
  Huawei Ascend, Cambricon, Iluvatar, Enflame, Furiosa, and other catalog-backed
  profiles without changing vendor metric names or native label keys.
- `node` always identifies the device's Synthetic Node and never the real
  Kubernetes Node that hosts the centralized `kasim-telemetry` Pod.
- Downstream PromQL that already consumes a `node` label no longer needs to
  derive device ownership through `kube_pod_info`, preventing devices from
  multiple simulated Nodes from collapsing onto one real Node and being
  filtered during resource-pool membership matching.
- Added two regression layers: a fast two-Synthetic-Node attribution test and
  a real Kind compatibility test proving that the telemetry Pod runs on a real
  Node while each NVIDIA sample still identifies its Synthetic Node.
- Synchronized Helm, CLI, bilingual online documentation, and release
  contracts to `0.4.1`.

### Upgrade impact

This upgrade does not change the Scenario transport, CRDs, scheduling resource
names, vendor metric families, value model, or existing Scenario Instances.
The supported Kubernetes range remains 1.30–1.36. ServiceMonitor remains an
explicit option and existing settings can be preserved during the upgrade.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and a
  Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.4.1`; the same
  minimal runtime image contains `/kasim-controller` and `/kasim-telemetry`.
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.4.1`.
