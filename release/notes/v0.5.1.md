# 中文

## kube-accelerator-sim v0.5.1

v0.5.1 修正集中式模拟遥测与现有监控后端的设备归属兼容性，同时保持原厂
exporter 的指标名、`HELP`、`TYPE`、单位和原生 label。每条逐设备指标只额外增加
统一的 `node` label，明确指向生成该设备的 Synthetic Node，避免通过 telemetry
Pod 所在真实节点错误归属设备。

### 主要变化

- 所有逐设备指标增加 `node="<Synthetic Node>"`；DCGM 的 `Hostname`、AMD 的
  `hostname` 等原厂节点 label 保持不变，并与 `node` 指向同一个模拟节点。
- Synthetic Node 增加
  `feature.node.cloud.xiaoshiai.cn/accelerator-model.name="<model-id>"`，指标中的
  `modelName` 使用相同的规范化型号 ID，例如 `nvidia-h200`。
- 同一张模拟卡在所有指标 family 中稳定复用相同的设备索引和 UUID；NVIDIA
  DCGM family 保持 `gpu`、`UUID`、`device`、`pci_bus_id` 等原厂 label 契约。
- 利用率统一输出为 `0–100`；健康值统一为 `0` 表示正常、非零表示故障。功耗、
  温度、显存、时钟和 counter 仍按相关且确定性的模拟负载生成。
- 可选 ServiceMonitor 在抓取阶段移除目标注入的 `namespace`、`pod`、`container`
  label，防止集中式 telemetry Pod 被误判为业务工作负载。
- 单个 Node Group 的多个 Accelerator Pool 只能共享同一型号；不同型号必须拆分
  为独立 Node Group，从而保证节点级型号 label 不产生歧义。
- Telemetry Catalog 升级为 `v1alpha3`，修订 `2026-08-10.1`，固定摘要为
  `sha256:817178bb388bf36a25c869b9c7e7352a0e3cba3a1a8465d21c7e8bb1e28914a0`。

### 升级说明

此次升级不修改 Scenario CRD、调度资源名或 Kubernetes 集群生命周期。已有
Scenario Instance 会由新版控制器重新投影节点型号 label；遥测指标会在下一次
抓取时呈现新的兼容 label。支持范围仍为 Kubernetes 1.30–1.36。

如果下游 PromQL 曾通过 `kube_pod_info` 把 telemetry Pod 所在真实节点关联到设备，
应改为优先读取指标自己的 `node`，并仅在该 label 缺失时才使用其他回退逻辑。

### 发布产物

- GitHub Release：Linux amd64/arm64、macOS amd64/arm64、Windows amd64 原生
  `kasim` CLI 归档，以及校验和、SBOM、发布证据和 Sigstore 签名。
- Docker：`ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.1`，同一最小
  运行时镜像包含 `/kasim-controller` 与 `/kasim-telemetry`。
- Helm OCI：`oci://ghcr.io/linkmaq/charts/kasim-runtime`，版本 `0.5.1`。

# English

## kube-accelerator-sim v0.5.1

v0.5.1 fixes device ownership compatibility between centralized simulated
telemetry and existing monitoring backends while retaining native exporter
metric names, `HELP`, `TYPE`, units, and labels. Every per-device series adds
only a common `node` label identifying its Synthetic Node, avoiding accidental
attribution to the real Node that hosts the telemetry Pod.

### Highlights

- Every per-device series adds `node="<Synthetic Node>"`. Native exporter Node
  labels such as DCGM `Hostname` and AMD `hostname` remain present and identify
  the same Synthetic Node.
- Synthetic Nodes add
  `feature.node.cloud.xiaoshiai.cn/accelerator-model.name="<model-id>"`, and
  metric `modelName` values use the same canonical model ID, such as
  `nvidia-h200`.
- One simulated device reuses the same device index and UUID across all metric
  families. NVIDIA DCGM families retain native labels including `gpu`, `UUID`,
  `device`, and `pci_bus_id`.
- Utilization values use the `0–100` range. Health uses zero for healthy and a
  non-zero value for unhealthy. Power, temperature, memory, clocks, and
  counters remain correlated and deterministic.
- The optional ServiceMonitor drops target-injected `namespace`, `pod`, and
  `container` labels during scraping so the centralized telemetry Pod is not
  mistaken for an application workload.
- Multiple Accelerator Pools in one Node Group must share one model. Distinct
  models must use distinct Node Groups so the Node-level model label is
  unambiguous.
- The Telemetry Catalog advances to `v1alpha3`, revision `2026-08-10.1`, pinned
  at `sha256:817178bb388bf36a25c869b9c7e7352a0e3cba3a1a8465d21c7e8bb1e28914a0`.

### Upgrade notes

This upgrade does not change the Scenario CRD, scheduling resource names, or
the Kubernetes cluster lifecycle. Existing Scenario Instances are reprojected
with the model label by the new controller, and telemetry exposes the new
compatibility labels on the next scrape. Kubernetes 1.30–1.36 remains
supported.

Downstream PromQL that joined `kube_pod_info` to attach the telemetry Pod's
real Node should prefer the metric's own `node` label and use other identity
fallbacks only when that label is absent.

### Artifacts

- GitHub Release: native `kasim` CLI archives for Linux amd64/arm64, macOS
  amd64/arm64, and Windows amd64, plus checksums, SBOM, release evidence, and a
  Sigstore signature.
- Docker: `ghcr.io/linkmaq/kube-accelerator-sim-controller:0.5.1`; the same
  minimal runtime image contains `/kasim-controller` and `/kasim-telemetry`.
- Helm OCI: `oci://ghcr.io/linkmaq/charts/kasim-runtime`, version `0.5.1`.
